# 11: 修复硬性规则 9 执行不稳——AI 凭空假设客户属性

**Type:** task

**What to build:** L2 演示(demo-03)发现:真实模型在可见信息未提供"代发关系"时,首轮凭空称客户为「代发客户」——违反提示词硬性规则 9(不使用任何未在"可见客户信息"中给出的客户信息)。验收准备期间的复现演示另发现同源病灶:画像无客户姓名时,模型把策略卡骨架中的〔客户称呼〕填空标记原样输出为 [客户姓名]/[你的名字] 占位符。两处均并入本票。需让模型对该规则的遵循稳定可测。

**Blocked by:** None(独立小票).

**Status:** ready-for-human

实现口径:问题在提示词层面的规则遵循,候选手段(可组合):①提示词加反例(「不可说客户是代发客户/三方客户/贵宾,除非在可见信息中列出」);②输入侧显式列出「可见信息未覆盖的属性类型不得提及」;③输出后校验:在领域层对 manager 回复做客户属性提及检测(与可见信息比对),命中即降级重试或剥离(检测词表从画像字段派生,不写死)。验收以自动化测试为准:给定不含某属性的可见信息,断言经理回复(伪实现脚本 + 提示词内容)不含该属性断言句式。

- [x] 领域层或提示词层防护落地,回归测试覆盖"凭空假设客户属性"场景。
- [x] 真模型演示 demo-03 同场景重跑,首轮不再出现"代发客户"式假设。
