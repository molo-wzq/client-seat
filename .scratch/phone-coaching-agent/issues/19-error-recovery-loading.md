# 19: 错误可恢复与首屏加载态

**What to build:** 初始目录加载有反馈、失败可重试;操作类错误可关闭,不再是一行无法消除的红字。

**Blocked by:** None.

**Status:** ready-for-human

## 用户问题

- 打开应用时,`App.tsx:34-49` 并行拉取画像/素材/通话目录,期间无任何加载提示,名册短暂空白,慢网络下像「没有生客」。
- 初始加载失败只设一行 error 文案,页面照常渲染空名册,且该错误无法关闭、无重试,用户只能刷新整页。
- 操作类错误(快速开始、接通、发送失败等)同样是一行不可关闭的红字(`src/App.tsx:132-136`、`src/ui/CallStep.tsx:106-110` 等)。

## 改动范围

- `App` 增加初始加载状态:首屏目录拉取期间显示加载提示(BusyHint)。
- 初始加载失败:错误信息 + 「重试」按钮,点击重新拉取目录。
- 操作类错误:在现有内联红字基础上提供关闭手段(如「×」),不引入全局 toast 体系。
- 保持内联错误样式与 `role="alert"`,不新增错误状态机。

## 前后对照验收

- 前:断开 API 刷新页面 → 静默空名册/一行红字,只能整页刷新。
- 后:刷新先见加载提示;失败时见错误 + 「重试」,点击重试成功后正常渲染;操作错误可一键关闭。
- 自动化:App 层测试覆盖「初始加载失败 → 重试成功」路径。

## Comments

- 2026-09-09 已实现:首屏目录加载期间主区显示 BusyHint「正在准备桌面…」(数据到位前不再渲染空名册);初始加载失败显示「目录加载失败:<原因>」+ 重试按钮,点击重新拉取;操作类错误(快速开始/接通/找回等)红字后带「×」可关闭。App.test.tsx 新增「目录加载反馈与重试」两条用例。待人工验收前后对照。
