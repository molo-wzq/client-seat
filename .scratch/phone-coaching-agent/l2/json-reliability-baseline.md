# JSON 输出可靠性基线与复测记录(票 12)

- 日期:2026-09-09
- 模型:mimo-v2.5(`token-plan-cn.xiaomimimo.com/v1`);温度 0.7,max_tokens 16384
- 采样工具:`l2/json-reliability-probe.ts`(手动运行);场景矩阵:3 画像(P01/P02/P03)× 4 场景(开场/软拒绝/资金话题/明确拒绝)= 12 轮/次
- 降级判定:宽口径——规则 10 要求 signal/goal 每轮必填,经理轮输出缺任一元数据即计入;票面所述「模型未返回 JSON 的纯文本降级」是其主要真子集

## 探测:网关 JSON 模式支持

`response_format={"type":"json_object"}` 连续 2 次调用均 HTTP 200 且 content 为可解析 JSON → **支持**,方案①可行。

## A/B 对比(各 12 轮,同场景矩阵)

| 条件 | 降级轮 | 降级率 | 记录文件 |
| --- | --- | --- | --- |
| 改造前(无 response_format) | 2/12 | 16.7% | `json-reliability-sample-before.json` |
| 改造后(response_format=json_object) | 0/12 | 0.0% | `json-reliability-sample-after.json` |

**统计效力声明**:每组 12 轮为方向性证据(2/12 vs 0/12,Fisher 精确检验不显著),用于确认量级与演示缺口相符,不作为「降级率已显著降低」的统计证明;需更强结论时增大 N 复测。

改造前的 2 处降级均在「资金话题」场景(经理长回复更易散文漂移),与 L2 四段演示的缺口一致:演示阶段共 4 段对话出现 6 次纯文本降级(见 `demo-conversations-02-05-小结.md` 缺口 2),量级与 16.7% 相符。

## 结论

采纳口径①(请求层 JSON 输出模式):对话请求发送 `response_format={"type":"json_object"}`,纯文本降级路径保留作兜底。降级轮补抽取(口径②)无需引入。转写分析请求本轮不启用 JSON 模式——分析失败本就显式抛错、无静默降级面,且票 12 的问题域是对话轮元数据;分析侧如需同类改造另行验证。

## 方法备注与局限

- 改造前基线通过临时 stash 适配器改动采样;两次采样各为 12 轮单遍,样本量小,比率视为量级参考而非精确估计。
- JSON 模式并非硬保证:网关行为变化或极端截断时仍可能降级,领域层 `product-core` 对 usedCardId 的已发布卡校验继续兜底策略路径质量;若未来复测降级率回升,口径②(降级轮补抽取)是既记录在案的升级路径。
- before/after 结果文件由 `sample` 模式的输出名参数区分;早期采样靠手工改名留存,复现链以本说明为准。
