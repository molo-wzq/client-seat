## 三类生客验收(roadmap L2-06:三类生客下均能自然推进或体面退出)

| 类型 | 画像 | 轮数 | 结果 |
| --- | --- | --- | --- |
| 顺利推进 | P02 阿姨(真实) | 6 | 预约周五到访+加微信,取得下一步 ✓ |
| 顺利推进(话少) | P03 定期客户(真实) | 8 | 续存确认+发现他行线索+约定 1 月回访 ✓ |
| 软拒绝 | S1 推脱型(合成) | 5 | 接住降压、降级为发资料,体面收口 ✓ |
| 明确拒绝 | S2 拒绝型(合成) | 2 | 接住致歉即收口,无纠缠 ✓ |

**结论:三类生客下均能自然推进或体面退出;不同画像的实际策略路径明显不同(P02/P01 走 SC2 现状了解,P03 因无资金线索直接走 SC3,S1/S2 分别走降压降级与接住收口)——「画像差异引起明显不同的沟通策略」在真实模型上成立。**

## 演示驱动的产品修复

- 推理模型兜底:mimo-v2.5 偶发把最终 JSON 放入 `reasoning_content` 而 `content` 为空,原适配器直接报「返回为空」。已修复(src/adapters/openai-model-adapter.ts):reasoning 可解析出结构化输出则采用;思维链文本绝不当作对话播出。附 3 项单测。

## 缺口与改进清单(只记录,不在本轮改产品)

1. **硬性规则 9 执行不稳**(demo-03):AI 首轮把 P03 称作「代发客户」——可见信息中并无此属性,属凭空假设。候选改进:提示词中对「不得假设客户属性」给出反例;或产品侧在输入中显式列出「禁止提及的属性类型」。
2. **JSON 输出可靠性不足**:4 段演示出现 6 次纯文本降级,降级保证不中断但丢失策略引用/信号/目标元数据(结果页策略路径变稀)。候选改进:使用模型 JSON mode / function calling;或对降级轮补一次轻量结构化抽取。
3. **明确拒绝未留服务渠道**(demo-05):比 C-S02 模板保守,渠道价值丢失。候选改进:提示词收口规则中加「收口前可留一句自我介绍+联系渠道,一句为限」。
4. **轮内语义漂移**(demo-02 末轮):把「都是三年的定期」理解为提前支取顾虑。影响小,观察即可。
