# 策略卡模板

Status: 草案,待真实素材验证(L1-03)

策略卡是从案例分析(`case-analysis-template.md`)提炼的最小可复用策略单元,是后续对话智能体唯一可检索的策略输入。术语以根目录 `CONTEXT.md` 为准。

## 使用原则

1. 一张卡只写一个可复用策略。若同一打法在不同客户信号下有不同的下一步,拆成多张卡。
2. 策略卡记录"何时用、为了什么、按什么顺序做什么、怎么说的一般原则、何时停"——**不记录逐字台词**。参考话术只是理解策略的示例,复用的是动作链,不是原句。
3. 每张卡必须能追溯到来源案例与转写片段(轮次区间)。
4. 状态为"草稿"的卡不可被对话检索;只有人工确认"已发布"后才可使用。
5. 无法确认的信息写"未知",不猜测补全。

## 模板正文

```markdown
# 策略卡 SC-〔编号,如 C01-SC1〕:〔卡名,动宾结构,如"自报来历时先给退路"〕

- 状态:草稿 | 已发布   ← 只有"已发布"可被对话检索
- 来源案例:〔案例分析文件名,如 C01-xxx.md〕
- 来源片段:〔轮次区间,如第 5–9 轮〕
- 提炼人 / 日期:〔姓名 / YYYY-MM-DD〕

## 触发信号

〔在什么客户信号下使用这张卡。信号必须可观察——客户说了什么、处于什么可见状态;不是猜测的内心动机。可多条,逐条列出。〕

## 适用场景

〔业务场景与关系背景限定,如"存量生客首次触达、无预约直接来电"。与触发信号的区分:场景是背景前提,信号是当轮可见线索。〕

## 当前目的

〔使用这张卡时想取得的单一主要结果,动宾结构。一张卡一个目的;目的变了应换卡。〕

## 动作链

〔按序列出 2–5 个关键动作。这是策略卡的核心,必须完整、有序、可执行——读卡的人不回听录音也能照此行动。每步一行:动作 + 这一步为什么存在(一句)。〕

1. 〔动作一〕——〔为什么〕
2. 〔动作二〕——〔为什么〕
3. …

## 表达原则

〔从动作生成具体措辞时的约束,逐条写。例:"先说一句打扰致歉,不反复道歉";"不主动报收益数字";"单轮不超过两句"。〕

## 参考话术

〔素材原话 1–2 句(标轮次)+ 骨架改写。标注:仅供理解策略,不要求逐字复用。〕

- 原话:〔"…"(第 N 轮)〕
- 骨架:〔保留动作逻辑、替换具体信息的改写,如"您好,我是XX银行〔网点〕的〔姓〕,您之前〔信息来源〕…"〕

## 适用条件

〔这张卡成立的前提,逐条写,如"客户尚未明确拒绝""已知客户是本行存量客户"。不满足时不得使用本卡。〕

## 停止条件

〔出现什么信号时停止使用本卡,并写明转向:转其他策略还是结束对话。例:"客户明确说不需要→停止,转体面收口";"客户连续两轮单字回应→停止施压,给退路收尾"。〕
```

## 自检(提交前逐项确认)

- [ ] 触发信号全部可观察,无内心动机猜测
- [ ] 动作链脱开原录音仍可执行,顺序明确
- [ ] 参考话术只作示例,卡内无"必须原样说出"的要求
- [ ] 停止条件写明了转向(换卡或结束)
- [ ] 能追溯来源案例与轮次区间;全文脱敏
