# 案例分析模板

Status: 草案,待真实素材验证(L1-02)

对一段优秀录音或转写稿做整体拆解,回答三个问题:这通电话发生了什么、为什么有效、哪些可以复用。术语以根目录 `CONTEXT.md` 为准。

与策略卡的关系:案例分析解释原始案例;策略卡(`strategy-card-template.md`)是从中提炼的、可被对话复用的最小策略单元。一份案例分析通常提炼 1–3 张策略卡,两者同时保留。

## 填写规则

1. 只写素材中可观察到或可合理推断的内容;无法确认的信息写"未知",不猜测、不补全。
2. 一律脱敏:客户用"客户A"代称,不出现姓名、电话、账号、身份证号;真实产品名替换为"某产品/某理财"。
3. 引用客户或经理的原话时标注轮次(如"第7轮"),保证可追溯到转写片段。
4. 拆解前先跑素材质量检查表(`material-quality-checklist.md`),在文首记录结论。
5. 区分"已知事实"与"推测":推测内容前加"(推测)"。

## 模板正文

```markdown
# 案例 C〔编号〕:〔一句话概括,如"生客首次触达,从防备到同意到店面谈"〕

- 素材来源:〔文件名或转写稿路径〕
- 分析人:〔姓名〕
- 分析日期:〔YYYY-MM-DD〕
- 质量检查结论:〔通过 / 有保留通过 + 一句话说明;剔除片段见 §4 各阶段标注〕

## 1. 场景

〔这通电话的客观背景:客户与经理的关系基础、触达渠道、通话前铺垫(如短信/活动留资)、涉及的业务或产品类型。区分已知事实与推测。〕

## 2. 客户状态(通话开始时)

〔可观察的初始状态:态度(防备/中性/好奇)、处境线索(如资金在他行、关注某类产品)、初始意愿。只写可观察到的,不写内心动机。〕

## 3. 总体目标

〔经理这通电话想取得的最终结果,一句话。注意总体目标通常不是"卖出产品",而是取得某个合理下一步。〕

## 4. 对话阶段

〔按沟通目的的变化划分阶段,一般 2–5 个。阶段划分依据是"经理想要的东西变了",不是时间均匀切分。每个阶段填一张表。〕

### 阶段 N:〔阶段名,建议从目标层级取词:建立身份可信度/降低防御/判断沟通意愿/了解必要需求/争取合理下一步〕(第 X–Y 轮)

| 字段 | 内容 |
| --- | --- |
| 阶段目的 | 〔本阶段想取得的单一主要结果,动宾结构〕 |
| 客户信号 | 〔本阶段客户给出的可观察线索,含原话引用+轮次;开场阶段写"无(通话刚接通)"并描述初始状态〕 |
| 推进逻辑 | 〔为什么在这个信号下、为这个目的,采取下面的动作——决策理由〕 |
| 关键动作 | 〔1–3 个可观察动作,每条一行:动作+它服务什么〕 |
| 代表话术 | 〔1–2 句原话引用+轮次,注明对应哪个关键动作〕 |

〔重复上表直至覆盖全部阶段。质量检查中剔除的片段,在对应阶段标注"第X–Y轮已剔除,原因:…"。〕

## 5. 优秀原因

〔逐条列出值得复用的做法,每条指向具体阶段/关键动作并说明为什么。禁止"沟通流畅""有亲和力"这类不可复用的空泛评价。同时列出做得一般或不适用的动作(如有)——通话结果成功不代表所有动作优秀。〕

## 6. 实际结果

〔通话的客观结局:客户答应了什么/拒绝了什么/停在什么状态;轮数或时长;是否有约定事项。只写事实。〕

## 7. 可复用条件

〔这套打法迁移到新对话的前提:客户类型、关系基础、业务场景、渠道。同时写明不适用的情形(如"客户明确在气头上时不适用")。〕

## 自检(提交前逐项确认)

- [ ] 所有"未知"未被猜测补全
- [ ] 每条优秀原因都指向具体关键动作,而非整体印象
- [ ] 策略与原话已区分:阶段表能说明动作逻辑,原话只是例证
- [ ] 全文无姓名、电话、账号、真实产品名
- [ ] 阶段划分依据沟通目的变化,可向他人复述
```
