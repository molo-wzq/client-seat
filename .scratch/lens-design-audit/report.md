# 基于《游戏设计艺术》的透镜复审

日期：2026-10-02。范围：当前 Client Seat 的布置、通话、结算、同客户重试、来源反馈与已配置模型的一组真实试跑。

按 [作者官方透镜](https://deck.artofgamedesign.com/)核对了 17 个相关视角；名称、版本边界与一手链接详见 [research.md](research.md)。下述诊断与改进是本项目的设计应用,不是作者对产品的评价。

## 改动的重点

游戏原来有“客户席、策略卡、复盘”,但缺少贯穿一局的问题与可核对的重玩发现。本轮补成“选观察点 → 按画像回应 → 用原话核对 → 同客户改变回应 → 两局对照”。不增加客户分数、成交奖励、合成策略或替经理选卡。

| 问题及证据 | 修复 | 验证 |
| --- | --- | --- |
| 开局只有泛泛观察,结算没有回到同一问题 | 可选接住顾虑／核对条件／明确下一步／自由观察;对局保持问题,结算按客户实际原话定位入口 | 完整 UI 流程与真实模型试跑;无相关原话时如实说明,不判定达标 |
| 重试只是另开空局,前局没有可用关联 | 持久保存同客户原局关联及观察点;逐回应并列客户原话、经理原话、用卡与版本 | HTTP/领域/UI 联合回归;原局清理时本局仍能复盘,可重试加载 |
| 人工纠正素材后旧局来源会改变;标题错位可能借用别的素材 | 本轮保存验证过的用卡名、来源片段;指定 id 不做标题兜底,旧标题重名视为无法可靠定位 | 修改素材/移除当前卡后旧局证据不变;无快照旧局、来源失效和重名测试 |
| 产品参数和开局版本不足以解释历史差异 | 新局保存产品参数,后续生成沿用本局参数;各轮另存实际版本;旧数据缺项明确标注 | 参数与版本回归;对照时提示参数变化或缺失 |
| 滚动与失败恢复打断玩家,普通断网可能重复发送 | 接近底部才跟随;保留新草稿;快捷回复遇草稿先追加;所有中断先同步落库,未能核对时暂缓发送 | 流式阅读位置、新草稿、已保存但断网、再次加载和中文输入法回归 |
| 真实回复扩大了产品事实,演示脚本把“先别帮我报名”当同意 | 生成规则依次补清流动性、报名/资金截止、活动/产品对象;脚本仅认明确许可,不硬填20万或附赠微信许可 | 非授权句、分离许可和真实迭代样本;记录失败样本,不只保存好结果 |
| 开场示例和共用通话逻辑仍诱导资格/资金截止断言;收入称谓凭年龄猜测 | 统一通话逻辑与事实边界,窗口不当作资格,删除资金截止示例;收入与工作/退休状态只按可见信息 | 全提示词复审与实际开场复测;策略来源原话保留,不可照抄其不适用参数 |
| 用卡归因把错误表达包装成降摩擦;事实核对初版又误报开场缺条款 | 现有元数据调用增加本局参数与可见画像,输出事实核对候选;只检查明确断言,不把未罗列完整条款当错误 | 两段式接口保持两次调用,隐藏牌与观察点不传入;候选优先定位,未记录候选不表示通过核验 |
| 新观察问题在暗绿牌桌上对比度不足 | 调整文字/边框颜色;实时核对候选默认收起,参数按需展开 | 实机截图复查,窄屏操作检查 |

实现问题分别记录于 [01](issues/01-purposeful-replay.md)、[02](issues/02-evidence-snapshot.md)、[03](issues/03-player-attention.md)、[04](issues/04-consent-and-facts.md)。前次 [game-design-audit](../game-design-audit/report.md) 的画像引导、轮数提示与故障恢复继续保留。

## 再用同一组透镜检查

| 透镜 | 本轮复查结论 | 仍需验证 |
| --- | --- | --- |
| Essential Experience | 观察问题贯穿实际原话、打法、来源与再试 | 玩家是否能独立解释一个关键动作 |
| Surprise | 同客户重试可以看真实回应差异,保留原局 | 差异是否带来有价值的发现,不是随机噪声 |
| Curiosity | 开局选择想弄明白的问题,不强制配合成交 | 哪个问题最能引发新手好奇 |
| Endogenous Value | 策略卡连接到当时来源,不用卡数制造成就 | 玩家是否主动打开证据并理解适用条件 |
| Problem Solving | 客户可追问、保留和拒绝,观察经理如何处理具体顾虑 | 不同画像与真实素材覆盖是否足够 |
| Flow | 保护阅读位置、输入和恢复;解释按需展开 | 长局等待、阅读负担与操作节奏的真人表现 |
| Goals | 可以选观察点或自由观察,随时结束而不需打满12轮 | 用户会不会仍把成交当自己的胜利 |
| Skill | 核对原话与动作,不评价扮演客户的用户 | 是否能迁移到另一段真实通话 |
| Challenge | 不以强推次数、捏造资金或更长局数提高难度 | 观察任务对新手/熟手的难度差异 |
| Meaningful Choices | 不把询问/否定当报名授权,微信与报名分开 | 真模型在更多语气、引用和反问下的表现 |
| Control | 开始、结束、重试与权威记录一致;明确披露重生成替换本轮 | 多设备、极端网络和长时间离开后的体验 |
| Feedback | 实际原话、归因候选、事实核对候选与参数区分;来源不被事后改写 | 归因及核对模型仍可能漏报/误报 |
| Interest Curve | 有观察问题开局,有原文发现与对照入口结尾 | 兴趣曲线和自发重玩需要真人观察 |
| Character | 保留电话牌桌、客户席与明牌的项目身份 | 美术个性是否提高理解,而非分散注意 |
| Character Traits | 画像与快捷回复不补资金;隐藏信息隔离延续 | 多局扮演一致性与更广画像适配 |
| Character Function | 玩家做客户回应,经理行动,裁判只提供可核对候选 | 玩家能否正确区分三者职责 |
| Playtesting | 自动回归、实机操作与真实模型迭代分别记录 | 真人试玩未完成,见 [playtest.md](playtest.md) |

## 真实模型迭代记录

本轮使用实际配置模型和当前已发布卡,没有改写策略素材。客户为 P02,共同开场为“喂,是小李啊”。保存了 9 局、19 次经理回应（p4 两局,p5/p6/p7/p8/p9/p10/p11 各一局）,包含失败样本。针对门槛/先别报名/不想锁住资金的同一句回应依次检查生成与解释;p10/p11 追加已确认代发关系后的取用追问。原话与元数据见 [real-playthrough.json](real-playthrough.json)。另做一局零发言的手机重试/立即结束检查,不计入模型样本。保留用户原有进行中对局及输入草稿,没有导出该局。

| 版本 | 观察到的问题或行为 | 处理 |
| --- | --- | --- |
| p4 | “这个不锁钱”“钱放哪儿还是哪儿”超出无须立即转入的事实 | p5 区分时间安排、取用保证与客户授权 |
| p5 | 已说先不报名并问资格,仍编造“占名额”和资金月底到位 | p6 分开报名截止与资金日期,禁止编造稀缺资格 |
| p6 | 把产品的三方存管对象套到活动,把 T+1 扩写为到期到账 | p7 独立列活动对象,限制混用与自动到账推断,补事实核对候选 |
| p7 | 核对候选把开场没列全部条款、未重述画像当疑点 | p8 裁判补可见画像,仅针对明确断言;实时候选折叠 |
| p8 | 条件回复已说明代发对象且未办理报名;开场仍说“正好能搭上”,裁判准确标出资格缺依据,第二轮候选仍夹有正确事实复述 | p9 去掉开场“客户可参加”的诱导,修正共用通话逻辑里的资金月底到位和窗口压力;候选仍不作裁决 |
| p9 | 开场先核对资格,未直接保证能参加;但问“您单位的工资”,与年长画像/未知工作状态不协调 | p10 将收入称谓与资格名称分开,未知收入说资金,不凭年龄补职业或退休状态 |
| p10 | 同句回应明确“先不报”并核对关系,不再补出工作单位;追加“参加后能否随时取”追问时正确说明一天/七天与 T+1,但“活动本身只是登记资格”仍可能缩小活动未知限制 | p11 要求活动持有/退出条件未提供时明确未知,不得用产品参数或“只是登记”代答 |
| p11 | 同句问询与追加取用追问均明确活动条件还需确认、不保证随时能取,两次重申未授权不代办;没有编造名额或资金月底截止 | 本次样本修复目标得到实际回应支持;不凭提示词断言所有后续生成永不出错 |

本轮试跑是小样本故障复现与复测,没有控制所有生成随机性,也不是跨画像能力评测。修正提示词不能被当作硬性事实保证,裁判核对也只是候选。p11 裁判仍把“活动具体条件需确认”标成混用倾向,这条没有原话支持的明确错误,是需要人工否定的误报;开场的条件式关联也不等于已确认资格。界面不会据这些候选打分或宣告达标,不能用它们做自动质量裁决。旧错误样本保留,不会回填新的“正确”依据。

## 验证和收口边界

最终验证：`npm test` 31 个文件通过,264 项通过、14 项跳过;跳过项由 `MIMO_SMOKE` 环境开关控制,没有将其记作通过。本轮真实模型样本单独记录。`npm run typecheck`、`npm run build`、`git diff --check` 均通过。核心验证包括隐藏信息隔离、只认本轮已发布卡、无用卡不伪造依据、来源快照、参数/版本、原局清理、授权否定、断流恢复、输入草稿与滚动位置。

桌面 1440×900 两栏对照,手机 390×844 单列对照;文档宽度分别 1425、375,无横向溢出。实机确认手机重试后零轮也能立即结束并显示空局事实,再打开历史局保留三轮原话与 p11 版本。检查参数展开与来源边界、对照后续长行、通话输入与结束操作。临时视口在交付前恢复。

本次完成的是可复现设计缺陷的修复与复审。长时间兴趣、实际技能迁移、三类画像的全面模型适配与真人理解仍未证实,不能宣称“已经永远没有问题”或取得“专业游戏设计师认证”。[真人试玩表](playtest.md)记录下一层验证的具体观察与修复触发条件。
