# 透镜驱动的游戏设计改进

Status: ready-for-human

依据：用户要求基于《游戏设计艺术》审查并修复。名称与问题依据 [一手研究](research.md)，具体改进是本项目的设计推论。

## 本轮可验证问题

1. 本质体验、好奇、目标、技能：用户仅能泛泛地聊天，开局与结算缺少同一个观察问题。
2. 有意义的选择、惊喜、兴趣曲线：同客户重试虽保留原局，却没有持久关联与实际原文对照。
3. 反馈、内生价值：结算根据当前素材轮次定位来源；后续纠正素材会改变过去对局的证据。
4. 心流、控制：生成增量会把正在阅读旧轮次的玩家拉到底部；失败恢复和快捷回复会覆盖正在写的草稿。
5. 有意义的选择、反馈、人物功能：真实试玩中“无须立即转入”被扩写成“不锁钱”;演示脚本误认报名关键词,并填入未获授权的金额/微信许可。

## 实现与验收

- 选客户时可选观察点（接住顾虑／核对条件／明确下一步／自由观察）；只存作玩家元信息，不传入经理或裁判输入。
- 对局保留观察问题；结算给出相关客户原话、经理原话和核对提问。没有相关原话时明确说明；不把关键词检出当作动作达标。
- 同客户再试保留观察点、原局关联；结算按回应顺序并列两局原文、用卡记录与提示词版本。不得声称对应阶段相同、模型随机差异等于进步或单变量因果。原局已清理时仍可查看本局和重试加载。
- 新经理轮保存当时验证过的策略卡名、来源和原始片段；这些证据不进入后续模型输入。旧局从当前库回溯时标记未保存当时快照。
- 新局同时保存虚拟产品参数,经理沿用本局参数;复盘可直接核对。每个经理轮保存实际生成版本,避免开局后规则升级而冒充旧版本。
- 仅在接近底部时自动跟随，阅读旧轮次时显示查看最新按钮。快捷回复遇草稿先填入再由玩家发送，生成失败保留新草稿并提供恢复失败发言的选择。
- 所有断流先核对落库记录,不能把传输失败当作未发送;无法核对时暂缓发送、保留草稿,重新加载后再确定是否恢复。
- 修正真实试玩发现的活动时间/取用保证混淆与演示脚本非授权误判,保留普通拒绝计数规则。
- 覆盖持久化、HTTP 入口、隐私边界、回放旧数据、保留策略、失败恢复及读历史的回归；浏览器检查桌面和窄屏完整流程。

## 保留边界

继续使用真实素材与全部已发布策略卡、三次累计拒绝规则、12 轮上限、客户扮演与只读明牌。不扩大种子素材，不增加客户分数或成交奖励。明确结束按钮即时结束；自然语言拒绝规则的进一步调整需单独结合原规格审议。

专业质量需要真人试玩验证理解、兴趣与技能迁移。本轮修复可复现的软件/反馈缺陷并对真实模型迭代复测；小样本、候选裁判不能证明所有生成永不出错。未验证体验假设与模型漏报/误报边界单独记录,不以“通过所有透镜”代替真人验收。
