# 《游戏设计艺术》透镜的一手资料与本项目应用

日期：2026-10-02（Asia/Shanghai）

## 依据与边界

《The Art of Game Design: A Book of Lenses》作者是 Jesse Schell。出版社说明把透镜作为不同视角的一组提问，反复构建、试玩和修改设计；第三版目录包含迭代与试玩章节。因此透镜适合帮助发现缺口，不是通过几项自动测试便能取得的专业认证。[出版社书目及目录](https://www.routledge.com/The-Art-of-Game-Design-A-Book-of-Lenses-Third-Edition-3rd-Edition/Schell/p/book/9781138632097)

[Schell Games 官方图书入口](https://schellgames.com/art-of-game-design/)直接链接到[官方 Deck of Lenses 应用](https://deck.artofgamedesign.com/)。网页正文需要 JavaScript；本次核对了该页面引用的[公开应用脚本](https://deck.artofgamedesign.com/js/app.95e37080.js)中的 `resources.LensList`：名称、描述、问题和路由均可读。脚本哈希可能随更新改变；下表优先链接官方应用的相应卡面。链接中的位置仅用于当前应用导航，不作为跨版本透镜编号。没有使用网上流传的全书 PDF，也没有把第三方读书笔记当作一手证据。

下表的“已核实关注点”是简短概括；“项目审查问题”与“可验证改进方向”**是本次应用推论，不是书中原话或作者对本项目的评价**。项目定位依据根目录 `CONTEXT.md` 和前次审查：玩家扮演客户，AI 扮演经理，明牌只读，结算解释沟通行为；不能把客户配合成交当作玩家胜利。

## 透镜与项目审查问题

| 一手核实的透镜名称 | 已核实关注点 | 项目审查问题（应用推论） | 可验证改进方向（应用推论） |
| --- | --- | --- | --- |
| [Essential Experience／本质体验](https://deck.artofgamedesign.com/#/card/2) | 核心体验及其实现 | 玩家能否在一通电话后理解经理为什么这样做，还是仅看了模拟聊天？ | 布置时给出一个具体观察任务；结算回到该任务的证据轮次。避免以信息堆叠替代体验。 |
| [Surprise／惊喜](https://deck.artofgamedesign.com/#/card/4) | 令人感兴趣的意外 | 同一客户换回应后，是否能发现经理的不同打法？ | 允许对比两局真实策略路径；随机噪声、凭空编造的资金或权益不能充当惊喜。 |
| [Curiosity／好奇](https://deck.artofgamedesign.com/#/card/6) | 玩家想探究的问题 | 入座前有什么值得观察的悬念？结果是否回答了“经理有没有接住我的顾虑”？ | 让玩家从少量学习观察点中自选；保留自由扮演，不透露经理不可读的隐藏信息。 |
| [Endogenous Value／内生价值](https://deck.artofgamedesign.com/#/card/7) | 游戏内事物的价值 | 策略卡、明牌和复盘对玩家有什么实际价值？ | 把卡名连接到当前动作及原文证据；不直接用卡数量、回合数量制造学习成就。 |
| [Problem Solving／问题求解](https://deck.artofgamedesign.com/#/card/8) | 需要解决的难题 | 客户回应是否提出了有辨识度的沟通难题？一味点默认回复是否就能完成所有体验？ | 用画像已有事实提供不同顾虑入口；重试保留画像但允许主动改变一个回应，观察策略适配。 |
| [Flow／心流](https://deck.artofgamedesign.com/#/card/21) | 目标、注意及成长 | 主任务会不会被大量画像、全卡架和结果统计打断？生成等待期间玩家是否失去上下文？ | 主界面优先当前来话与回应；解释按需展开；恢复后保留当前目标和草稿，不让等待改变扮演任务。 |
| [Goals／目标](https://deck.artofgamedesign.com/#/card/32) | 清楚可达的目标 | “完成一局”究竟是打满 12 轮、让经理成交，还是看懂一个动作？玩家是否能选自己的目标？ | 说明随时结束；提供少量可选观察任务，每局以证据回答任务。此项也有[官方独立文章](https://schellgames.com/blog/lens-of-goals)支持。 |
| [Skill／技能](https://deck.artofgamedesign.com/#/card/34) | 所需技能及练习 | 游戏练的是银行知识、打字能力，还是识别客户信号与关键动作？ | 任务应聚焦观察、比较和解释动作；快捷回复降低打字负担，不能替用户编造事实。 |
| [Challenge／挑战](https://deck.artofgamedesign.com/#/card/38) | 难度、层次及变化 | 新手和熟手是否得到同样杂乱的内容？更强拒绝是否只是让 AI 更久缠着客户？ | 以观察任务复杂度、提示可见度形成层次；避免把增加强推次数作为难度。覆盖范围仍受已发布策略卡和真实素材约束。 |
| [Meaningful Choices／有意义的选择](https://deck.artofgamedesign.com/#/card/39) | 选择的意义与数量 | 愿意听、追问、保留、拒绝、结束，是否改变经理应做的动作？是否存在“一直点同一按钮”的万能路径？ | 分析分支的实际回应和策略；结束选择须即时生效；快捷按钮的标签与发送内容必须一致。 |
| [Control／控制](https://deck.artofgamedesign.com/#/card/59) | 预期和影响结果 | 玩家能否可靠地继续、结束、重试？玩家能控制客户意愿，却是否误以为能直接控制 AI 用哪张卡？ | 明牌解释其只读性质；停止、断流、恢复和重开都应与实际落库状态一致。 |
| [Feedback／反馈](https://deck.artofgamedesign.com/#/card/63) | 当下目标所需信息 | 用卡高亮究竟证实了动作，还是只是模型提出的归因？拒绝与停止是否给出真实、及时的后果？ | 分开已知事实、归因候选、卡内参考；反馈可回到原文轮次；未确认如实显示，不能奖励不存在的动作。 |
| [Interest Curve／兴趣曲线](https://deck.artofgamedesign.com/#/card/69) | 兴趣随过程变化 | 前 30 秒有没有钩子？连续来回会不会平直？结算有没有一个让人想重试的发现？ | 以一个观察问题开局，以一个关键转折收尾，再试只改变一个回应；平直问题须用真人观察验证。 |
| [Character／独特性格](https://deck.artofgamedesign.com/#/card/50) | 游戏可爱的独特之处 | “客户席＋明牌”是否形成清晰身份，还是被通用聊天 UI 淹没？ | 保留本项目电话牌桌的可辨识体验；先修可用性，不因为想增加个性而增加无关复杂操作。 |
| [Character Traits／人物特征](https://deck.artofgamedesign.com/#/card/87) | 特征如何呈现在行动 | 画像事实是否能被玩家自然扮演？模型是否记住双方已说内容并避免凭空补画像？ | 客户已知事实与可自由表达的意愿区分；核对快捷话术、记忆、已认识关系及隐藏信息泄漏。 |
| [Character Function／人物功能](https://deck.artofgamedesign.com/#/card/86) | 人物承担什么功能 | 用户、经理和裁判的职责有没有混淆？ | 玩家做真实客户回应，经理示范策略，裁判解释原文动作；结算不能把用户拒绝判为失败。 |
| [Playtesting／试玩](https://deck.artofgamedesign.com/#/card/103) | 试玩目的及观察方法 | 谁来玩？用什么证据判断玩家学会了？自动测试能证明什么、不能证明什么？ | 新手、熟手分别观察首次入座、首轮回应、结束与复盘；不提示答案，记录困惑和自发重试，比较修复前后。 |

## 迭代不是一枚已核实的同名透镜

出版社第三版目录的迭代章节为 “The Game Improves through Iteration”。本次读取的官方当前卡组**未找到题为 Iteration 的卡片**。因此报告可以使用“迭代过程＋试玩透镜”，不应编造 “Lens of Iteration” 或一个编号。[出版社目录](https://www.routledge.com/The-Art-of-Game-Design-A-Book-of-Lenses-Third-Edition-3rd-Edition/Schell/p/book/9781138632097)

另一个常见误用是把 Character 译成角色塑造；该卡讨论的是游戏本身可爱的独特特质。本项目人物塑造要用 Character Traits、Character Function，必要时用 Character Transformation，而不是把这些不同名称混为一谈。[官方 Character 卡](https://deck.artofgamedesign.com/#/card/50)、[官方 Character Traits 卡](https://deck.artofgamedesign.com/#/card/87)

## 对本轮修复的可操作判据（本次设计推论）

1. **开局可理解**：玩家能明确自己是客户、自己有自由拒绝和结束的权利，并能选定或理解本局一个具体观察问题。
2. **选择有后果**：客户的实际信号改变经理的合理下一步；明确结束不应被普通产品异议吞没。需同时检查既有规则与源规格，不能靠透镜引用声称规则已获作者背书。
3. **反馈可核对**：结算回答观察问题，指向关键轮次；动作归因、经理事实边界和未知信息有可区分表现。
4. **重玩有目的**：同客户再试保留原局，重新开局时仍知道本次在观察什么；两局可以用实际原文和策略路径比较，不能以不可控模型随机性宣称进步。
5. **验证有层次**：代码回归与浏览器走通验证可用性；真实模型分支样本验证适配；真人试玩验证理解、兴趣和迁移。未进行的一层标记未验证。

先将可复现问题修复并复测，再对同一透镜重新检查。停止条件应是“当前可核对范围内没有新的未处理缺口，且体验假设已明确标记”，而不是宣称“已经永远找不出问题”。长期兴趣、真实客户心理和技能迁移，不能只凭源代码或设计者自玩证明。

## 与本项目已有决定的边界

`docs/adr/0001-l1-minimal-demo.md` 明确延后软拒绝／明确拒绝素材与独立拆解复核，策略资产起点受真实素材限制。透镜提出“挑战多样性”并不授权编造真实素材或发布合成种子策略卡。`CONTEXT.md` 也要求合成素材明确标注且不得提炼为产品种子策略卡。本次方向应优先改进任务可理解性、体验后果及有证据的反馈，不用扩大策略来源掩盖现有限制。

## 证实和未证实

- 已证实：表中英文名称存在于官方公开 Deck app，概念概括与公开卡面问题相符；Goals 另经官方博文交叉核对；出版社目录存在迭代与试玩章节。
- 本次未证实：用户所读中文版本的译名、页码或编号；透镜作为统一资格认证的存在；作者对本项目的具体评价；全部透镜覆盖或长时间真人体验效果。
- 所有中文审查问题、实现方向和收口判据均为对本项目的设计应用推论；其有效性仍需产品证据及试玩检验。
