# 电话对练：游戏设计审查与优化记录

日期：2026-10-02

## 设计判断

这是一个从客户视角体验策略的学习游戏。玩家的有效选择是“愿意听、追问、透露信息、犹豫、拒绝、结束”，经理的策略与反馈构成学习回报。它适合用清晰的角色、有限的通话节奏、可核对的反馈和低成本重试形成循环，不需要把客户配合成交当作胜利，也不需要加分数替代真实体验。

旧版最突出的问题是：外观已经像牌桌，但角色引导、客户回应边界和复盘后的重试还不够清楚；部分界面解释还会把参考动作包装成本轮事实。以下改动围绕这些问题完成，没有改成选卡战斗或考试平台。

## 已完成的优化

| 问题与证据 | 优化后的行为 |
| --- | --- |
| 布置只教入座操作，玩家不知道是否必须帮助经理成交；入座只显示标题与隐藏牌数量。 | 简短三步玩法，解释真实回应与提前结束；完整已知画像可读，隐藏牌可展开预览。 |
| 探询快捷回复直接写“我的钱在股市”“钱都存着定期”；“万”会误触产品阶段，“理财经理”也能误触产品词。 | 不替客户补写资金事实，依经理明确谈到的活动或产品分组；已认识关系以画像为准。补了金额与经理身份的误判回归。 |
| 轨道只有12格，无剩余提示，容易被理解为必须打满；领域结束原因未经核实就写“体面收口”。 | 展示还可回应几次，最后三轮提示；明确可以提前结束。上限只说明本局结束，不声称经理完成了优秀收口。 |
| 明牌把动作链首项标为本轮“关键动作”；已有经理回复但无用卡时仍显示等待亮牌。 | 分开本轮匹配依据候选与卡内动作参考；信号、目的标注解释候选；未匹配如实显示未确认。 |
| 复盘很长、没有阅读起点、来源片段始终展开；“再来一局”必须重新选客户。 | 优先定位卡外数字或未确认轮次，附事实统计；原始来源按需展开；同一客户一键重试，新建通话并保留原局。统计不代表质量。 |
| 手机先堆完整画像再显示通话；中等宽度的三栏挤压主操作；空聊天占据大块高度。 | 窄屏画像默认折叠，中等宽度牌架移到下一行；空通话给出明确开场提示并减少留白；进入新幕定位到内容起点。 |
| 中文输入法 Enter 可能误发；加载失败无原地重试；零回合不能结束；结束落库但结果失败仍允许发言。 | 输入法保护与键盘提示；加载重试；零回合退出；结束状态立即同步，结果失败可重试且不重复结束。 |
| 慢回复期间离开旧局再开新局，旧局迟到回调会替换新客户（测试先复现失败）；停止流式显示后客户端恢复草稿，而服务器仍可能保存该轮（UI与领域测试先复现失败）。 | 卸载后断流且忽略旧回调，父层校验会话id；进入历史读取最新状态；停止显示后等待权威记录，恢复读取按会话串行等待生成落库，避免重复发送。 |

## 仍需试玩检验的设计选择

这些是待验证假设，不是已证实的体验收益，不能靠静态代码审查宣布解决。

1. **三次拒绝规则的感受**：现有玩法累计第三次拒绝才收口，且包括明确终止意图。既有规格记录了“明确结束应例外”的分歧，本轮保留该已定规则，并保证玩家随时可以主动结束。真人试玩应分别观察普通产品拒绝、忙、明确要求挂断；若终止意图仍被继续争取，应优先评估即时收口例外，而非加更强的销售激励。
2. **真实模型的策略适配**：现有画像来自真实素材，P02属于已相识的维护关系；活动与种子策略偏代发场景。不能通过虚构身份或自动发布新卡填空。应采样不同画像的对话，核对是否先确认活动条件、是否真正接住顾虑、是否可靠引用已发布卡。
3. **长期重玩动力与迁移学习**：同客户换一个回应能否帮助经理学到动作，而不是记台词，需要真人观察。先记录玩家是否自发重试、是否能指出一个具体动作；没有收益时，应缩短解释或改善案例覆盖，不直接堆等级、每日任务与评分。

## 本轮收口标准

完成主流程审查、恢复边界复查和修复后的测试及浏览器复核；在以上检查范围内没有再发现新的可复现阻断项。此结论不等于游戏永远没有问题，也不等于已通过真实玩家的长期体验验证。
